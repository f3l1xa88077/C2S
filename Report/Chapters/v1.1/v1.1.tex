Version 1.1 (v1.1) of C2S refined v1 with a core focus on accessibility, debugging, and integration. In v1, basic requirements were implemented, which led to the eventual failure of the microSD component and memory management issues. This version placed system requirements at a higher priority, almost developing a virtual version before hardware development occurred, to minimise the risk of failure as much as reasonably possible.

Just like the previous board, the version milestones were ordered to ensure planning was executed in the correct order and no aspects of the design were skipped or shortcut:

\begin{enumerate}
    \item Systems Planning
    \item Capabilities
    \item CIS Agreements (N/A)
    \item Component Selection
    \item Development
\end{enumerate}

The purpose this version aimed to serve was to be a universal board for FlatSat/HAB/CubeSat integration until requirements were further solidified and budget was available for final versions i.e., a product to fill the payload bay of all three. If successful, the integration procedure and interface would be greatly simplified via a single board, so prepping the board for a HAB is a matter of ensuring its connection was the same as used on FlatSat and vice versa.

At the time of development, the need for a functioning payload was greater than the need for a CubeSat payload, hence the rationale behind this version. Nevertheless, this version employed little new methods or components that weren't already introduced or implemented on previous versions, simply more structured and organised.

It should also be noted, that the v0.1 compression tests were being conducted as this version's requirements were being written, so this was the first version to use information from those tests to inform hardware and software choices.
